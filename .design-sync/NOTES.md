# design-sync NOTES

## Fixes

- [GENERAL] `exported PascalCase symbols: 0` on first build → root cause: `packages/react/package.json` only declared types via the modern `exports["."].types` field; the converter's `dts.mjs` `projectFor()` resolves the type-check entry from the legacy `pj.types`/`pj.typings` field only (ignores `exports`), so it looked for a nonexistent `packages/react/index.d.ts` and silently found zero exports → fix: added a top-level `"types": "./dist/index.d.ts"` field to `packages/react/package.json` (standard practice for exports+types interop anyway, not a converter-only hack).
- [GENERAL] `--entry` is required when building from the DS's own source repo (`node_modules/@sahari-ui/react` doesn't exist there) — pass the absolute path to `packages/react/dist/index.js`, plus `--node-modules packages/react/node_modules`.
- `titleMap`: several storybook titles use combined/compound story files that don't match a single export name 1:1 — mapped `"Fields"` → `Input` (Input's ONLY story file uses this title) and `"Badges&Tags"` → `Badge` (Badge's only story file; Tag has no dedicated stories of its own — it appears only inside Badge's "Tones" story, so Tag currently ships with a floor card, no generated preview). `"Choices"` (Checkbox/Radio/Switch combo demo) and `"Navigation"` (BottomNav/Tabs combo demo) mapped to `null` (excluded) since those components already have their own dedicated, correctly-titled story files — the combo titles are redundant in-context demos, not the components' primary coverage.
- `titleMap`: all 10 `Compositions/*` and `Foundations/Theme` stories (Booking, Comments, Discover, Feed, Messages, Notifications, Profile, SessionRating, SahariMobile, Theme) mapped to `null` — these are full-page/theme compositions, not single exported components, and are intentionally out of scope for the component sync (see "Re-sync risks" below re: `ui_kits/`).
- `overrides`: `[GRID_OVERFLOW]` on first validate for 4 components — `Card` (FlatAndTactile story), `Input` (Fields story), `Skeleton` (PostLoading story) all render wider than a grid cell → set `cardMode: "column"`. `Toast` positions content via `ToastViewport` (fixed/portal) in its "Viewport" story → set `cardMode: "single"`, `primaryStory: "Tones"` (the non-portal, representative story). Targeted rebuild cleared all 4 warnings; validate is clean.

## Sync scope decision (user-directed, not a converter default)

- This repo's claude.ai/design project ("Sahari Design System", projectId `9526ae71-9898-4147-98c2-c5067e442fef`) pre-existed this sync with hand-authored content: `guidelines/**` (brand color/type/elevation/motion cards), `ui_kits/**` (full app + dashboard mockup compositions), `assets/**`, `uploads/**`, `SKILL.md`, `_adherence.oxlintrc.json`, `.thumbnail`/`thumbnail.html`. **User explicitly chose to KEEP all of this untouched** — this sync's `finalize_plan` writes/deletes are scoped to `components/**`, `tokens/**`, `fonts/**`, `_vendor/**`, `_preview/**`, `_ds_bundle.js`, `_ds_bundle.css`, `styles.css`, `README.md` (replacing the existing lowercase `readme.md`), `_ds_sync.json`, `_ds_needs_recompile` only — NOT the default full atomic-path deletes review. **A future re-sync must preserve this scope decision** — do not let a generic "review non-empty project's file list for files this build doesn't produce" pass delete `guidelines/`, `ui_kits/`, `assets/`, `uploads/`, `SKILL.md`, `_adherence.oxlintrc.json`, `.thumbnail`, or `thumbnail.html` without re-confirming with the user first.
- Verified before keeping `guidelines/`: `packages/tokens` builds byte-identical CSS custom property values to the old hand-authored `tokens/*.css` that shipped with the project, so the guideline cards (which reference `var(--purple-500)` etc.) keep rendering correctly even though `tokens/**` gets replaced by the real build.

## Re-sync risks

- Tag has no dedicated story file — if a `tag.stories.tsx` is ever added, it needs its own title (not nested inside Badge's) to get its own preview coverage.
- The kept `guidelines/`/`ui_kits/` content is NOT regenerated or verified by this sync — if `packages/tokens` values ever diverge from what those hand-authored cards assume, they will silently go stale. No automated check catches this; a human should periodically eyeball them.
- `readme.md` (lowercase, hand-authored) is being replaced by the converter's generated `README.md` (uppercase) — this is intentional (see scope decision above), but note the case change on case-sensitive filesystems/tools.
- [GENERAL] Toast's "Viewport" story: `compare.mjs`'s storybook-side capture screenshots the `#storybook-root` element's own bounding box, not the full viewport. Since `Viewport`'s content is `position: fixed` (a `ToastViewport` rendered bottom-center) and the story's own layout box is small (280px, near the top), the fixed child renders outside that bbox and is missed — the storybook-side screenshot comes back blank even though the real storybook page shows the toast correctly. The preview side already has a portal-detection fallback (full-page screenshot when it detects foreign body children), so only the storybook side is affected — an asymmetry in the capture tool, not a component/preview defect. Verified by loading `.design-sync/sb-reference/iframe.html?id=components-toast--viewport&viewMode=story` directly in a browser: the toast renders correctly after its fade-in. Graded `match` (not close/mismatch) on this basis. A future re-sync will hit the same blank-looking sheet for any fixed-position story — don't mistake it for a regression; re-verify the same way (load the iframe URL directly) rather than trusting the sheet alone. Not fixable via config/previews — would need a capture-logic change in `.ds-sync/storybook/compare.mjs` (viewport-sized or fixed-position-aware capture on the storybook side).
